# felt-web — etapas para fechar a UI

Tudo aqui é UI pura, com dados no formato do `view` (fixtures e mão roteirizada). Regras, avaliação de mãos e validação continuam no servidor: quando a tela precisa de algo que exige regra (a mão de alguém, quem ganhou), isso entra como campo do `view`, e o front só mostra. Cada etapa é uma PR.

| Etapa | O que entra | Campos novos no `view` |
|---|---|---|
| E1 · Combinações e showdown | Tabela de combinações (painel), selo "sua mão", resultado do showdown (faixa com quem venceu e com qual mão, cartas vencedoras destacadas, assento vencedor) | `you.hand`, `result.winners[]` |
| E2 · Informação da mesa | Selos D/SB/BB, all-in, registro de ações ("Mara pagou 50"), anúncios para leitor de tela ("Sua vez") | `seats[].role`, `log[]` |
| E3 · Sentar e sair | Escolher lugar livre, diálogo de buy-in, sair com cash-out, "aguardando jogadores", modo espectador | `you.seat` nulo, `minBuyIn`/`maxBuyIn`, `phase: "waiting"` |
| E4 · Blackjack completo | Fase de apostas (fichas e timer), banca revelando a carta virada, resultado por mão (ganhou, perdeu, empate, blackjack) | `phase: "betting"`, `seats[].outcome` |
| E5 · Conexão e erros | Faixa de reconectando/desconectado, toasts por código de erro, estados de carregamento | estado local (sem `view`) |
| E6 · Perfil e lobby | Nome, avatar (conjunto de SVGs), skin e verso no perfil, código de recuperação (mostrar, copiar, importar), apagar conta, mesas recentes | perfil (`/v1/me`) |
| E7 · Polimento | Passada em 390px em todas as telas, tema claro, reduced motion, revisão de acessibilidade | — |

Depois da E7: **guia da API** (`felt-server`), escrito a partir do que a UI precisa: tipos do `view` e dos eventos, mensagens do WebSocket, rotas HTTP, códigos de erro e o que cada campo significa.
